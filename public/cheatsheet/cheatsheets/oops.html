  11. Constructor

    A Constructor initializes
a newly created object.

In Java:

Constructor name must
match class name.

It has no return type.
    class Student {

    String name;

    Student() {

        name = "Rohit";

    }

}

  12. Parameterized Constructor

    class Student {

    String name;
    int age;

    Student(String name, int age) {

        this.name = name;
        this.age = age;

    }

}

Student s1 =
    new Student("Rohit", 21);

  13. Default Constructor

    In Java, if you do not
declare any constructor,

the compiler provides
a default no-argument
constructor.

If you declare your own
constructor, Java does not
automatically add that
default constructor.

    }

    Student(String name) {

    }

    Student(String name, int age) {

Call another constructor

  21. Encapsulation

    Encapsulation bundles data
and behavior together and
controls access to internal state.

Common Java approach:

private fields

+

public methods

  22. Encapsulation Example

    class BankAccount {

    private double balance;

    public void deposit(double amount) {

        if (amount > 0) {

            balance += amount;

        }

    }

    public double getBalance() {

        return balance;

    }

}

  23. Getter and Setter

    class Student {

    private String name;

    public String getName() {

        return name;

    }

    public void setName(String name) {

        this.name = name;

    }

}

  27. Abstract Class

    abstract class Animal {

    abstract void sound();

    void sleep() {

        System.out.println("Sleeping");

  28. Abstract Method

    abstract void sound();
    An abstract method
declares behavior without
providing an implementation
in that abstract declaration.

  29. Using Abstract Class

    abstract class Animal {

    abstract void sound();

}


class Dog extends Animal {

    @Override
    void sound() {

        System.out.println("Bark");

    }

}

  30. Can We Create Abstract Class Object?

    No.

You cannot directly instantiate
an abstract class.

Invalid:

Animal a = new Animal();


But you can use
an abstract-class reference:

Animal a = new Dog();

  48. Polymorphism

    Polymorphism means
"many forms".

The same interface,
method call or reference
can behave differently
depending on the object/type.

  49. Types of Polymorphism

    Compile-Time Polymorphism

→ Method Overloading


Runtime Polymorphism

→ Method Overriding
  + Dynamic Dispatch

  50. Method Overloading

    class Calculator {

    int add(int a, int b) {

        return a + b;

    }

    int add(int a, int b, int c) {

        return a + b + c;

    }

    double add(double a, double b) {

        return a + b;

    }

}

  51. Overloading Rules

    Methods have the same name

but different parameter lists.

Difference can involve:

Number of parameters

Parameter types

Parameter order


Return type alone
cannot overload a method.

  52. Method Overriding

    class Animal {

    void sound() {

        System.out.println(
            "Animal sound"
        );

    }

}


class Dog extends Animal {

    @Override
    void sound() {

        System.out.println("Bark");

    }

}

  53. Runtime Polymorphism

    Animal animal = new Dog();

animal.sound();
    Output:

Bark


The overridden instance method
is selected according to
the runtime object.

  54. Overloading vs Overriding

    OVERLOADING

Same method name

Different parameters

Usually same class

Compile-time resolution


OVERRIDING

Subclass provides a new
implementation of an
inherited instance method

Same signature

Runtime dispatch

  55. Can Static Methods Be Overridden?

    No, not in the normal
runtime-polymorphism sense.

Static methods belong
to the class.

A subclass may declare
a static method with the
same signature.

This is called:

Method Hiding

  56. Can Private Methods Be Overridden?

    No.

A private method is not
inherited as an accessible
member by the subclass.

Therefore it cannot
be overridden.

  57. final Keyword

    final variable

→ Cannot be reassigned
  after initialization


final method

final class

→ Cannot be extended

  60. Final Class

    final class Security {

}

  61. Association

    Association represents
a relationship between
independent objects.

Example:

Teacher

  62. Aggregation

    Aggregation is a
whole-part relationship
with relatively independent
lifecycles.

Example:

Department HAS-A Teacher

A Teacher can exist
independently of one
specific Department.

  63. Aggregation Example

    class Teacher {

    String name;

    Teacher(String name) {

        this.name = name;

    }

}


class Department {

    Teacher teacher;

    Department(Teacher teacher) {

        this.teacher = teacher;

    }

}

  64. Composition

    Composition is a strong
whole-part relationship.

The containing object
owns the contained part's
lifecycle in the model.

Example:

House HAS-A Room

  65. Composition Example

    class Engine {

    void start() {

        System.out.println(
            "Engine started"
        );

    }

}


class Car {

    private final Engine engine =
        new Engine();

    void start() {

        engine.start();

    }

}

  66. Aggregation vs Composition

    Aggregation

Weak ownership

Parts can usually exist
independently


Composition

Strong ownership

Part lifecycle is typically
controlled by the whole

  67. Association vs Aggregation vs Composition

    if (user1.equals(user2)) {

    System.out.println("Equal");

  75. == vs equals()

    For objects:

==

Compares reference identity


equals()

Can compare logical/content
equality depending on
its implementation.

  76. hashCode()

    hashCode() produces an
integer hash value used
by hash-based collections.

Important contract:

If two objects are equal
according to equals(),

they must return the
same hashCode().

  77. Immutable Object

    An immutable object's
observable state cannot
be changed after creation.

Common design:

final class

private final fields

Initialize in constructor

No mutating setters

Protect mutable fields
with defensive copies

  78. Immutable Class Example

    final class Student {

    private final String name;
    private final int age;

    Student(String name, int age) {

        this.name = name;
        this.age = age;

    }

    public String getName() {

        return name;

    }

    public int getAge() {

        return age;

    }

}

  79. Coupling

    Coupling describes
dependency between modules
or classes.

Generally preferred:

Lower coupling

because it can improve:

Maintainability

Testing

Flexibility

Reusability

  80. Cohesion

    Cohesion describes
how closely related
responsibilities inside
a module/class are.

Generally preferred:

High Cohesion

A class should have
a focused responsibility.

  81. Coupling vs Cohesion

    Good design often aims for:

  82. SOLID Principles

  83. Single Responsibility Principle

    SRP

A module/class should
have one focused reason
to change.

Avoid placing unrelated
responsibilities inside
one class.

  84. SRP Example

    class InvoiceCalculator {

    double calculateTotal() {

        return 1000;

    }

}


class InvoicePrinter {

    void print() {

        System.out.println(
            "Printing invoice"
        );

    }

}

  85. Open/Closed Principle

    OCP

Software entities should be:

Open for Extension

Closed for Modification


Design so new behavior
can often be added without
rewriting stable existing code.

  86. Liskov Substitution Principle

    LSP

Objects of a subtype
should be usable where
objects of the base type
are expected without
breaking the expected
behavioral contract.

  87. Interface Segregation Principle

    ISP

Prefer smaller,
focused interfaces.

Clients should not be
forced to depend on
methods they do not need.

  88. Dependency Inversion Principle

    DIP

High-level policy should
not depend directly on
low-level implementation details.

Both should depend on
abstractions.

  89. Dependency Injection

    interface MessageService {

    void send(String message);

}


class Notification {

    private final MessageService service;

    Notification(
        MessageService service
    ) {

        this.service = service;

    }

    void notifyUser() {

        service.send("Hello");

    }

}
    The dependency is supplied
from outside rather than
created directly inside
Notification.
