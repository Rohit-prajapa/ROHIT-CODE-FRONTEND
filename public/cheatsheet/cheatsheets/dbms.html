  41. Insertion Anomaly

    Insertion Anomaly:

You cannot insert
some information without
also inserting unrelated
information.

  42. Update Anomaly

    Update Anomaly:

The same fact appears
in multiple rows.

Changing only some copies
creates inconsistency.

  43. Deletion Anomaly

    Deletion Anomaly:

Deleting one record
accidentally removes
other useful information.

  44. First Normal Form — 1NF

    1NF requires values
to be atomic within
the relational design.

Avoid repeating groups.

Bad:

Student

Name: Rohit

Phones:
9876, 1234


Better:

Store phone values
as separate related rows.

  45. Second Normal Form — 2NF

    2NF:

Table must be in 1NF

AND

Every non-prime attribute
must be fully dependent
on the whole candidate key.

Main issue removed:

Partial Dependency

  46. Third Normal Form — 3NF

    3NF:

Table must be in 2NF

AND

It should remove problematic
transitive dependencies
of non-key attributes.

Simple interview idea:

Non-key attributes should
depend on the key,
not on other non-key attributes.

  47. BCNF

    BCNF =

Boyce-Codd Normal Form

For every non-trivial
functional dependency:

X → Y

X must be a Super Key.

BCNF is stricter than 3NF.

  48. Normal Forms Quick Revision

    1NF

Atomic values


2NF

1NF +

No partial dependency


3NF

2NF +

Remove problematic
transitive dependency


BCNF

Every determinant
must be a Super Key

  49. Functional Dependency

    Functional Dependency:

X → Y

means:

If two rows have the
same X value,

they must have the
same Y value.


Example:

Student_ID → Student_Name

  50. Full Functional Dependency

    Y is fully functionally
dependent on X when it
depends on the whole X

and not on a proper
subset of X.

  51. Partial Dependency

    Suppose composite key:

(Student_ID, Course_ID)


If:

Student_ID → Student_Name


Then Student_Name depends
only on part of the
composite key.

This is Partial Dependency.

  52. Transitive Dependency

    Example:

Student_ID → Department_ID

Department_ID → Department_Name


Therefore:

Student_ID

indirectly determines

Department_Name

  106. Atomicity

    Atomicity means:

All operations of a
transaction succeed

OR

All or Nothing.

  107. Consistency

    Consistency means a

    Isolation controls how

  109. Durability

    Durability means:

  116. Common Concurrency Problems

    Lost Update

Dirty Read

Non-Repeatable Read

Phantom Read

  117. Dirty Read

    Transaction A updates data
but has not committed.

Transaction B reads
that uncommitted data.

Transaction A rolls back.

B has read a value
that never became committed.

  118. Non-Repeatable Read

    Transaction A reads row X.

Transaction B updates
and commits row X.

Transaction A reads X again.

It may receive
a different value.

  119. Phantom Read

    Transaction A runs
a query returning
a set of rows.

Transaction B inserts/deletes
rows matching that query
and commits.

Transaction A repeats
the query.

The result set contains
new or missing rows.

  120. Lost Update

    Two transactions read
the same value.

Both update it.

One update overwrites
the effect of another.

This can cause a
Lost Update.

  150. Data Independence

    Data Independence means
changes at one schema level
can be made with limited
impact on higher levels.

Types:

  151. Physical Data Independence

    Changes in physical
storage should not require
changes to the logical schema.

Examples:

Change indexing

Change file organization

  152. Logical Data Independence

    Changes to the conceptual
schema should have limited
impact on external views
and applications.

Generally harder to achieve
than physical data independence.
